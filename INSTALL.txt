ReelDock 1.3.10

Source repository: https://github.com/AshCooperUK/ReelDock-v1.3

Build and run with Docker
-------------------------
Requires Docker Engine and Docker Compose on a Linux host.

1. Clone this repository and open its directory.
2. Copy .env.example to .env. Set REELDOCK_INSTALL_DIR to the absolute directory
   where this installation should keep its data and media. The Compose default
   is /DATA/AppData/reeldock-v13. Use an empty directory for a new installation.
3. Build the image:
   docker build -t reeldock:1.3-development .
4. Start the source installation:
   docker compose -f compose.yaml up -d --no-build
5. Open http://127.0.0.1:8821/setup on the Docker host to create your account.

The source-build service binds to loopback by default. Configure a verified public address
through setup when using a reverse proxy. Never expose the setup port directly
without reviewing the application's host and origin requirements.

The data and media directories are separate from the source checkout. Keep them
and the project VPN volumes when updating. Do not commit the .env file, browser
cookies, provider credentials or application databases.

Provider accounts and optional YouTube cookies are configured in the app.
Integrated Privado sign-in additionally requires an API key supplied to the VPN
container through REELDOCK_PRIVADO_API_KEY. This repository contains no provider
API key. WireGuard configuration uploads remain available.

The CasaOS template uses ghcr.io/ashcooperuk/reeldock-v1.3:1.3.10. Import
compose.casaos.yaml from the matching published release. Its host directories
are explicit paths for compatibility with the CasaOS importer:
   Media and downloads (/reeldock): /DATA/Media/reeldock-v13/data
   Application data (/data): /DATA/AppData/reeldock-v13/data
   VPN runtime: /DATA/AppData/reeldock-v13/vpn-run
   VPN state: /DATA/AppData/reeldock-v13/vpn-state
Edit these consistently in all service mounts and storage preparation before
installing somewhere else. REELDOCK_HOST_ROOT must match the media host path.
The storage helper creates the directories and permissions before the VPN,
web and worker start. Do not add blank Host volume entries in the CasaOS editor.
Keep the long-form volume entries and leave web/worker container names unset;
CasaOS otherwise changes the read-only flags or adds incompatible hostnames.
This template describes a fresh installation. Keep the existing storage and
VPN volume configuration when updating an installation using named volumes.
Source builds use compose.yaml and its REELDOCK_INSTALL_DIR setting instead.
The tag-triggered release workflow derives its package name from this repository.
No container is published simply by pushing the main branch.

CasaOS LAN setup
----------------
Leave the Web UI hostname and LOCAL_SETUP_URL blank. CasaOS opens its server
address on port 8821; the container listens on 8790. Automatic LAN setup is
enabled by REELDOCK_AUTO_LAN_SETUP=1 in the template. No HOST_IP substitution
or fixed server address is required.

Storage preparation briefly uses host networking to read the server's local
interface addresses and read-only /etc/hostname and /etc/hosts identity files.
It writes a protected, root-owned address snapshot in vpn-run, then exits.
ReelDock accepts direct home-network setup only on those trusted addresses,
with its existing Origin, CSRF and account checks. Unknown DNS-only aliases
show a link to the detected LAN IP. No caller-supplied hostname is saved or
automatically trusted. An explicit LOCAL_SETUP_URL remains an optional override.

Keep web and worker on their supplied service:vpn network setting; selecting
Bridge for those services replaces their shared VPN network. The preparation
service's host network is intentional and does not carry downloads.

Open ReelDock from CasaOS and choose "Skip — use locally" for LAN-only access.
Configure a separately verified HTTPS address in setup for public access.
After a server address change, rerun preparation and recreate web/worker so
they load the refreshed snapshot. Existing data and media directories stay put.

For a remote source-build installation that retains loopback binding, use an
SSH tunnel, then open http://127.0.0.1:8821/setup locally:
   ssh -L 8821:127.0.0.1:8821 your-user@your-server

Development
-----------
Install FFmpeg (including ffprobe) and the dependencies in requirements.txt
into a Python virtual environment.
The frontend uses Node.js 22 and pnpm 11.19.0:
   pnpm --dir frontend install --frozen-lockfile
   pnpm --dir frontend build

After building the frontend, checks can be run with:
   python -m unittest discover -s tests
   cd frontend
   node --test *.test.cjs *.test.mjs

A full Docker image build also compiles the native VPN interposer. Tests which
need optional external tools or an explicitly supplied NZB sample can skip when
those fixtures are unavailable. No downloaded media or account state is bundled.

Source changes after 1.3.10 — 2026-11-01
----------------------------------------
These changes are in the source branch. The published 1.3.10 image and release
assets are unchanged until a separate image release is published. Build the
source checkout to use these changes with Docker.

- Discover keeps imported VOD catalogues available when automatic refresh is
  paused, groups movie editions and TV episodes without losing exact download
  choices, and orders release dates using known years when exact dates are absent.
- Completed local downloads can retain metadata from their exact Discover
  request, including artwork and the matched movie year.
- YouTube downloads retain the exact selected video and use up to five automatic
  retries after the first attempt, while respecting cancellation, holds and
  current connection settings. Failure messages distinguish common causes.
- NZB connection failures distinguish authentication refusal from a provider's
  connection limit.
- Library optimisation creates checked HEVC or H264 copies, with optional AAC
  stereo audio and a 1080p limit that never enlarges smaller videos. Originals
  are retained. Files and folders show sizes and support name/size sorting.
- Optimisation jobs show progress and a separate collapsible Activity section.
  Validated copies can be saved beside originals using a clean title plus the
  selected profile, for example Movie Title (2020) HEVC.mkv. Existing files are
  never overwritten; unsupported/HDR sources are kept unchanged and copies must pass
  validation and save at least 5%.
- Guide Agenda honours Latest upload for both day groups and videos, with known
  uploads before forecasts and date-only entries. Favourites stay within their
  day/status group; filters and pagination retain the same video identities.

Optional existing-library mounts for source builds
-------------------------------------------------
Library optimisation is disabled by default. Set these variables in your local
.env before adding compose.library-optimise.yaml to your source Compose command:
   REELDOCK_EXISTING_TV_PATH=/absolute/path/to/TV Shows
   REELDOCK_EXISTING_MOVIE_PATH=/absolute/path/to/Movies
   REELDOCK_LIBRARY_WRITE_GID=1000
Replace these examples with existing directories and the group that already has
write access. The overlay refuses to create a missing host directory. It maps
read-only input views and separate writable views for checked copies. Review
permissions for the selected libraries; it does not change host ownership.

After building the source image, start it with:
   docker compose -f compose.yaml -f compose.library-optimise.yaml up -d --no-build
Select a file in Settings > Library optimisation and enable optimisation only
when ready. Encoding uses the CPU and can take hours. Check picture/audio
quality on your devices. Keeping the originals means new copies need additional
free disk space; it does not automatically reclaim the original space.

YouTube retries, NZB failure classification, optimisation validation/publication,
